## 1. MQTT

### 1.1 トピック

| トピック | 向き | QoS | `type` |
|---|---|---|---|
| `reray/v1/up/{id}/signal` | 端末 → サーバー | 1 | `signal` |
| `reray/v1/up/{id}/status` | 端末 → サーバー | 0 | `status` |
| `reray/v1/up/{id}/ack` | 端末 → サーバー | 1 | `ack` |
| `reray/v1/down/{id}/text` | サーバー → 端末1台 | 1 | `text` |
| `reray/v1/down/all/text` | サーバー → 全端末 | 1 | `text` |
| `reray/v1/down/{id}/ack` | サーバー → 端末1台 | 1 | `ack`【案】 |

- サーバーは `reray/v1/up/#` を購読する。
- `{id}` は `dev-NNN`。JSON の `src` と**一致しなければ捨てる**。

### 1.2 共通の項目(すべての JSON)

| 項目 | 型 | 必須 | 値・制約 | 無い・誤りのとき |
|---|---|---|---|---|
| `v` | 数値 | ◎ | `1` | 原本だけ残して捨てる |
| `type` | 文字列 | ◎ | トピックの末尾と同じ | 原本だけ残して捨てる |
| `src` | 文字列 | ◎ | 端末は `dev-NNN`(NNN は 1〜65534)、サーバーは `pc` | 原本だけ残して捨てる |
| `seq` | 数値 | ◎ | 0〜65535(送信元ごとの連番) | 原本だけ残して捨てる。**遺言にだけは無い** |
| `ts` | 数値 | ○ | UNIX 秒。**参考値**(正はサーバーの受信時刻) | 未定。**遺言にだけは無い** |

### 1.3 signal(上り)

```json
{"v":1,"type":"signal","src":"dev-001","seq":42,"ts":1791849600,"code":2,"pos":3,"via":"wifi"}
```

| 項目 | 型 | 必須 | 値・制約 |
|---|---|---|---|
| 共通の5項目 | | §1.2 | |
| `code` | 数値 | ◎ | 1〜31(1=SOS。一覧は共通仕様 01 で段階0に決める)。**未定義のコードも保存する** |
| `pos` | 数値 | △【案】 | ポジション番号 0〜255(0=場所なし)。無ければ 0 |
| `via` | 文字列 | ○ | `wifi` / `lora` |
| `x` | オブジェクト | △ | ハード試作だけにある追加項目。無視する(原本には残る) |

### 1.4 status(上り)

```json
{"v":1,"type":"status","src":"dev-001","seq":43,"ts":1791849630,"battery":80,"glass":true}
```

| 項目 | 型 | 必須 | 値・制約 |
|---|---|---|---|
| 共通の5項目 | | §1.2 | |
| `battery` | 数値 | △ | 0〜100(%)。測れなければ項目ごと省く |
| `glass` | 真偽 | △ | グラスと BLE でつながっているか |
| `via` | 文字列 | △ | 【修正案】LoRa の心拍を出口が直したときに `lora`。**項目名は合意待ち** |
| `online` | 真偽 | △ | ふだんは省く。遺言のときだけ `false` |
| `lat`・`lon` | 数値 | △【案】 | GPS の位置(10進の度)。取れなければ省く |

**遺言(Last Will)**:端末が黙って切れたときに、ブローカーが代わりに流す。`seq` と `ts` が**無い**ので、この形は特別に受け付ける。

```json
{"v":1,"type":"status","src":"dev-001","online":false}
```

### 1.5 ack(上り)

| 形 | 項目 | 必須 | 値 |
|---|---|---|---|
| 現行のたたき台 | `ack_src` | ◎ | `pc` |
| | `ack_seq` | ◎ | 届いた text の `seq` |
| 【修正案】 | `ack_mid` | ◎ | 届いた text の `mid`(= `messages.id`) |

```json
{"v":1,"type":"ack","src":"dev-001","seq":44,"ts":1791849601,"ack_src":"pc","ack_seq":7}
{"v":1,"type":"ack","src":"dev-001","seq":44,"ts":1791849601,"ack_mid":12}
```

- 合意前は**両方の形を受け付ける**。`ack_mid` があればそれを使い、無ければ `ack_seq` で直近の text を探す。どちらでも決まらなければ `acks` に入れず、`events` に `unmatched` で残す。

### 1.6 text(下り。サーバーが作る)

```json
{"v":1,"type":"text","src":"pc","dst":"all","seq":7,"mid":12,"ts":1791849600,"body":"北口に集合してください"}
```

| 項目 | 型 | 必須 | 値・作り方 |
|---|---|---|---|
| `v` | 数値 | ◎ | `1` |
| `type` | 文字列 | ◎ | `text` |
| `src` | 文字列 | ◎ | `pc` |
| `dst` | 文字列 | ◎ | 端末ID か `all`。トピックの `{id}` / `all` と同じにする |
| `seq` | 数値 | ◎ | サーバーが採番(`pc` の u16。65535 の次は 0) |
| `ts` | 数値 | ◎ | 送る時刻(UNIX 秒) |
| `body` | 文字列 | ◎ | 全角40文字まで【案】。上限は定数1つで持つ |
| `mid` | 数値 | ◎【修正案】 | `messages.id`。**先に DB に保存して id を得てから**流す |
| `icode` | 数値 | △【案】 | 指示コード。指示コードの形のときだけ |
| `pos` | 数値 | △【案】 | ポジション番号。指示コードの形のときだけ(`icode` とセット) |

- 指示コードの形でも `body` は入れる(サーバーが「ポジション名 + 指示の文」で作る)。LoRa では `icode` と `pos` だけを運ぶ。

### 1.7 本部に届いた(下り。サーバーが作る)【案】

```json
{"v":1,"type":"ack","src":"pc","seq":9,"ts":1791849601,"ack_src":"dev-001","ack_seq":42}
```

| 項目 | 型 | 必須 | 値・作り方 |
|---|---|---|---|
| `v`・`type`・`src`・`seq`・`ts` | | ◎ | `1`・`ack`・`pc`・サーバーの採番・送る時刻 |
| `ack_src` | 文字列 | ◎ | 受けた signal の `src` |
| `ack_seq` | 数値 | ◎ | 受けた signal の `seq` |

- signal を保存したら返す。重複で捨てた signal にも返す。

## 2. DB(SQL)

書き込むときにサーバーが渡す列と、その値の出どころ。

### 2.1 devices(端末)

| 列 | 型 | 渡す | 値の出どころ |
|---|---|---|---|
| `id` | VARCHAR(16) PK | ◎ | API の登録、または受信したトピックの `{id}` |
| `owner` | VARCHAR(64) | △ | API の登録・変更。受信で見つけた端末は空 |
| `online` | TINYINT(1) | ◎ | **サーバーの判定だけ**で更新【修正案】。遺言で 0 |
| `via` | VARCHAR(8) | △ | 最後に届いた signal / status の `via` |
| `battery` | TINYINT UNSIGNED | △ | status の `battery`。無ければ前の値のまま |
| `glass` | TINYINT(1) | △ | status の `glass` |
| `last_seen_at` | DATETIME(3) | ◎ | 何か届くたびにサーバーの受信時刻 |
| `pos` | TINYINT UNSIGNED | △【案】 | 最後に届いた signal の `pos` |
| `lat`・`lon` | DOUBLE | △【案】 | status の `lat`・`lon` |
| `created_at` | DATETIME(3) | ◎ | 行を作った時刻 |
| `registered` | TINYINT(1) | ◎【追加案】 | API で登録=1、受信で初めて見つけた=0 |

### 2.2 messages(送った文字)

| 列 | 型 | 渡す | 値の出どころ |
|---|---|---|---|
| `id` | INT UNSIGNED PK AUTO_INCREMENT | 自動 | text の `mid` になる |
| `seq` | SMALLINT UNSIGNED | ◎ | サーバーの採番(text の `seq`) |
| `dst` | VARCHAR(16) | ◎ | API の `dst` |
| `body` | VARCHAR(255) | ◎ | API の `body`。指示コードの形ならサーバーが作った文 |
| `kind` | VARCHAR(8) | ◎【案】 | `free` / `order` |
| `icode` | TINYINT UNSIGNED | △【案】 | API の `icode`(`order` のとき) |
| `pos` | TINYINT UNSIGNED | △【案】 | API の `pos`(`order` のとき) |
| `source` | VARCHAR(16) | ◎【案】 | `web` / `transcript` |
| `sent_at` | DATETIME(3) | ◎ | 保存した時刻 |
| `publish_state` | VARCHAR(16) | ◎【追加案】 | `sent`(PUBACK を受けた)/ `failed`(流せなかった) |

### 2.3 signals(届いた定型信号)

| 列 | 型 | 渡す | 値の出どころ |
|---|---|---|---|
| `id` | INT UNSIGNED PK AUTO_INCREMENT | 自動 | |
| `device_id` | VARCHAR(16) | ◎ | `src`(= トピックの `{id}`) |
| `seq` | SMALLINT UNSIGNED | ◎ | `seq` |
| `code` | TINYINT UNSIGNED | ◎ | `code` |
| `pos` | TINYINT UNSIGNED | ◎【案】 | `pos`。無ければ 0 |
| `via` | VARCHAR(8) | ○ | `via` |
| `device_ts` | DATETIME(3) | △ | `ts`(UNIX 秒)を ISO 8601 に直す。無ければ空 |
| `received_at` | DATETIME(3) | ◎ | サーバーの受信時刻(**こちらが正**) |

- `(device_id, seq)` に一意制約は**付けない**【修正案】。重複はコードで判定する(直近10分に同じ `device_id` と `seq`)。

### 2.4 acks(届いた確認)

| 列 | 型 | 渡す | 値の出どころ |
|---|---|---|---|
| `id` | INT UNSIGNED PK AUTO_INCREMENT | 自動 | |
| `message_id` | INT UNSIGNED | ◎ | `ack_mid`、または `ack_seq` から探した `messages.id` |
| `device_id` | VARCHAR(16) | ◎ | `src` |
| `acked_at` | DATETIME(3) | ◎ | サーバーの受信時刻 |

- `(message_id, device_id)` は一意。2回目は捨てる(最初の時刻を残す)。

### 2.5 message_targets(送った時の宛先)【追加案】

| 列 | 型 | 渡す | 値の出どころ |
|---|---|---|---|
| `message_id` | INT UNSIGNED | ◎ | 保存した `messages.id` |
| `device_id` | VARCHAR(16) | ◎ | `dst` の端末。`all` なら登録済みの全端末 |
| `via_at_send` | VARCHAR(8) | ◎ | 送った時の `devices.via` |

- 主キーは `(message_id, device_id)`。text を流す前に、messages と同時に書く。

### 2.6 positions・instruction_codes・transcripts【案】

| 表 | 列(◎=渡す) | 値の出どころ |
|---|---|---|
| `positions` | `no`◎、`name`◎、`place`△、`updated_at`◎ | W8 の API(`/api/positions`) |
| `instruction_codes` | `code`◎、`text`◎、`updated_at`◎ | `/api/instruction-codes`。一覧は共通仕様 01 と同じにする |
| `transcripts` | `id` 自動、`body`◎、`dst`◎、`speaker`△、`received_at`◎、`message_id`△ | `POST /api/transcripts`。`message_id` は配った messages.id |

### 2.7 events(原本)【追加案】

| 列 | 型 | 渡す | 値の出どころ |
|---|---|---|---|
| `id` | INT UNSIGNED PK AUTO_INCREMENT | 自動 | |
| `received_at` | DATETIME(3) | ◎ | 受信・送信した時刻 |
| `direction` | VARCHAR(8) | ◎ | `up` / `down` |
| `topic` | VARCHAR(255) | ◎ | MQTT のトピック |
| `payload` | TEXT | ◎ | 本文そのまま(4 KB 超は切り詰め) |
| `result` | VARCHAR(16) | ◎ | `accepted` / `duplicate` / `invalid` / `unmatched` / `sent` / `failed` |
| `note` | VARCHAR(255) | △ | 捨てた理由など(例 `v!=1`) |

### 2.8 時刻の書き方

- DB(MySQL)には **`DATETIME(3)` の UTC** で入れる(例 `2026-10-16 06:00:00.000`)。API で返すときに +09:00 の ISO 8601 に直す。
- MQTT の `ts` は UNIX 秒なので、`device_ts` に入れるときに `DATETIME` に変換する。
- 型は MySQL の書き方(`DATA_MODEL_2026-10-22.md` §1)。

## 3. 受信1件ごとに書く表

| 受信 | 書く表 |
|---|---|
| signal | `events` → (重複でなければ)`signals`、`devices`(`via`・`pos`・`last_seen_at`。無ければ `registered=0` で作る)→ 【案】端末へ `down/{id}/ack` |
| status | `events` → `devices`(`battery`・`glass`・`via`・`lat`・`lon`・`last_seen_at`・`online`) |
| 遺言 | `events` → `devices`(`online=0`) |
| ack | `events` → (対応づけられれば)`acks`、`devices`(`last_seen_at`) |
| text を送る(API) | `messages`・`message_targets` → MQTT に流す → `messages.publish_state`、`events` |
| 文字起こし(API)【案】 | `transcripts` → 「text を送る」と同じ流れ(`source = transcript`)→ `transcripts.message_id` |
