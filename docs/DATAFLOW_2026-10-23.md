# DATAFLOW — 受け取ったものを、DB と送り先に何を渡すか

> 更新: 2026-10-23 / 状態: **ドラフト**(実装のための早見表)
> MQTT で受け取ったメッセージ1件ごとに、**DB に書く値**と、**送り先(端末・画面)に渡す値**を、例つきでまとめたもの。
> 項目の定義は `FIELDS_2026-10-23.md`、表の定義は `DATA_MODEL_2026-10-23.md`、JSON の形は `INTERFACES_2026-10-23.md` が正。食い違ったらそちらに合わせる。
> 範囲は**災害用(今期)**。普段用の音声(【将来】)は `ARCHITECTURE_2026-10-23.md` §12。

## 早見表

| 受け取るもの | DB に書く表 | 送り先に渡すもの |
|---|---|---|
| signal(定型信号) | `events`・`signals`・`devices` | 端末へ「本部に届いた」【案】/ 画面へ新着(SOS なら目立たせる) |
| status(端末の状態) | `events`・`devices` | 画面へ端末の状態の変化 |
| 遺言(切れた) | `events`・`devices` | 画面へ「切れた」 |
| ack(指示が届いた) | `events`・`acks`・`devices` | 画面へ届いた数の更新 |
| 形が正しくないもの | `events` だけ | なし |
| (逆向き)画面・文字起こしアプリからの送信 | `transcripts`・`messages`・`message_targets`・`events` | 端末へ text / 指示コード |

MQTT に流すときの決まり(JSON の書き方・QoS・retain・接続)は §8。

- 「画面へ」は、SSE(`/api/stream`、【追加案】)で押し出す場合の中身。画面が取りに来る方式なら、同じ値を API が返す(`INTERFACES_2026-10-23.md` §4・§5)。
- 時刻は DB では UTC の `DATETIME(3)`、画面へは +09:00 の ISO 8601。
- 例の受信時刻は `2026-10-13 00:00:00.500`(UTC)とする。

## 1. signal(定型信号)

### 受け取る

```
トピック: reray/v1/up/dev-001/signal
{"v":1,"type":"signal","src":"dev-001","seq":42,"ts":1791849600,"code":2,"pos":3,"via":"wifi"}
```

### 処理の順番

1. `events` に原本を書く(この時点では `result` 未確定)
2. 確かめる(`v`・`type`・`src` とトピックの一致・`seq` の範囲)→ だめなら `events.result = invalid` で終わり
3. 重複を確かめる(直近10分に同じ `device_id` と `seq`)→ 重複なら `events.result = duplicate`。**DB はここで終わるが、端末への「本部に届いた」は返す**
4. `signals` に書き、`devices` を更新する
5. 端末と画面に渡す

### DB に書く

**events**

| 列 | 値 |
|---|---|
| `received_at` | `2026-10-13 00:00:00.500` |
| `direction` | `up` |
| `topic` | `reray/v1/up/dev-001/signal` |
| `payload` | 受け取った JSON そのまま |
| `result` | `accepted`(重複なら `duplicate`、不正なら `invalid`) |
| `note` | 空(捨てた理由があれば書く) |

**signals**(新規の1行)

| 列 | 値 | どこから |
|---|---|---|
| `device_id` | `dev-001` | `src` |
| `seq` | `42` | `seq` |
| `code` | `2` | `code` |
| `pos` | `3` | `pos`(無ければ `0`) |
| `n` | 空(NULL) | `n`(数を使う信号だけ。例 `20` は「16〜20 人」)【案】 |
| `via` | `wifi` | `via` |
| `device_ts` | `2026-10-13 00:00:00.000` | `ts`(UNIX 秒)を変換 |
| `received_at` | `2026-10-13 00:00:00.500` | サーバーの時計 |

**devices**(`dev-001` の行を更新。無ければ `registered = 0` で作る)

| 列 | 値 |
|---|---|
| `via` | `wifi` |
| `pos` | `3` |
| `online` | `1` |
| `last_seen_at` | `2026-10-13 00:00:00.500` |
| `created_at` | 行を作ったときだけ。受信時刻 |
| `registered` | 行を作ったときだけ。`0` |

### 渡す

**端末へ:本部に届いた【案】**(`INTERFACES_2026-10-23.md` §2.6)

```
トピック: reray/v1/down/dev-001/ack  (QoS 1)
{"v":1,"type":"ack","src":"pc","seq":9,"ts":1791849600,"ack_src":"dev-001","ack_seq":42}
```

| 項目 | 値 | どこから |
|---|---|---|
| `ack_src` | `dev-001` | 受けた `src` |
| `ack_seq` | `42` | 受けた `seq` |
| `seq` | `9` | サーバーの採番(`pc` の連番) |
| `ts` | 送る時刻 | サーバーの時計 |

**画面へ:新着**(SSE のイベント `signal`)

```json
{"device_id":"dev-001","owner":"山田","code":2,"pos":3,"position_name":"北口","via":"wifi","at":"2026-10-13T09:00:00.500+09:00"}
```

- 数を使う信号なら `"n":20` も渡す。「16〜20 人」の文は画面側で作る(`SIGNAL_FORMAT_2026-10-23.md` §2)。

- `owner`・`position_name` は DB(`devices`・`positions`)から足す。
- `code = 1`(SOS)なら、画面はどの画面にいても知らせる(FW-04)。

## 2. status(端末の状態)

### 受け取る

```
トピック: reray/v1/up/dev-001/status
{"v":1,"type":"status","src":"dev-001","seq":43,"ts":1791849630,"battery":80,"glass":true}
```

### DB に書く

**events**:signal と同じ形(`result = accepted` など)

**devices**(`dev-001` の行を更新。無ければ `registered = 0` で作る)

| 列 | 値 | どこから |
|---|---|---|
| `battery` | `80` | `battery`(無ければ前の値のまま) |
| `glass` | `1` | `glass`(無ければ前の値のまま) |
| `via` | 変えない | `via` があれば更新(LoRa の心拍【修正案】) |
| `lat`・`lon` | 変えない | あれば更新【案】 |
| `online` | `1` | 何か届いたので |
| `last_seen_at` | 受信時刻 | サーバーの時計 |

- status は `signals` のような履歴の表を持たない(最新の値だけ)。履歴は `events` の原本から引ける。

### 渡す

**画面へ:端末の状態**(SSE のイベント `device`。値が変わったときだけ)

```json
{"device_id":"dev-001","online":true,"via":"wifi","battery":80,"glass":true,"last_seen_at":"2026-10-13T09:00:30.000+09:00"}
```

端末へは何も返さない(status は QoS 0 で、確認は要らない)。

---

## 3. 遺言(端末が黙って切れた)

### 受け取る

```
トピック: reray/v1/up/dev-001/status
{"v":1,"type":"status","src":"dev-001","online":false}
```

`seq` と `ts` が無いが、この形は受け付ける。

### DB に書く

| 表 | 書く値 |
|---|---|
| `events` | 原本(`result = accepted`) |
| `devices` | `online = 0`(`last_seen_at` は**変えない**。最後に本当に届いた時刻を残す) |

### 渡す

**画面へ**:SSE `device` で `{"device_id":"dev-001","online":false, ...}`。

---

## 4. ack(端末に指示が届いた)

### 受け取る

```
トピック: reray/v1/up/dev-001/ack
{"v":1,"type":"ack","src":"dev-001","seq":44,"ts":1791849601,"ack_mid":12}
```

(合意前は `ack_src`・`ack_seq` の形も来る。`INTERFACES_2026-10-23.md` §2.4)

### DB に書く

| 表 | 列 | 値 |
|---|---|---|
| `events` | — | 原本。対応づけられなければ `result = unmatched` |
| `acks` | `message_id` | `12`(`ack_mid`。無ければ `ack_seq` から探す) |
| | `device_id` | `dev-001` |
| | `acked_at` | 受信時刻 |
| `devices` | `online`・`last_seen_at` | `1`・受信時刻 |

- 同じ `message_id` と `device_id` がもうあれば、`acks` には書かない(最初の時刻を残す)。

### 渡す

**画面へ**:SSE `ack`

```json
{"message_id":12,"device_id":"dev-001","acked_at":"2026-10-13T09:00:01.000+09:00","wifi":{"total":5,"acked":4},"lora":{"total":1,"acked":0}}
```

- `wifi`・`lora` の数は `message_targets` と `acks` から数え直す(「5台中4台に届いた」)。

## 5. 形が正しくないもの

| 例 | DB | 渡す |
|---|---|---|
| JSON として読めない、`v` が 1 でない、`src` とトピックが違う など | `events` だけ(`result = invalid`、`note` に理由) | なし |

**サーバーは止まらない。** 未知の項目があるだけなら、正しいものとして受け付ける。

## 6. 時間で起きること(MQTT の受信なし)

| きっかけ | DB | 渡す |
|---|---|---|
| Wi-Fi の端末から 90秒、LoRa の端末から 15分なにも届かない | `devices.online = 0` | 画面へ SSE `device`(`online: false`) |

## 7. 逆向き:画面・文字起こしアプリから端末へ送る

MQTT で受け取るものではないが、DB と MQTT の両方に書くので一緒に載せる。

### 受け取る(HTTP)

| 入口 | 例 |
|---|---|
| 管理画面 `POST /api/messages` | `{"dst":"all","body":"北口に集合してください"}` / 指示コードなら `{"dst":"dev-001","icode":1,"pos":3}` |
| 文字起こしアプリ `POST /api/transcripts`(災害用) | `{"dst":"all","body":"北口に集合してください","speaker":"本部"}` |

### DB に書く(**先に書いてから** MQTT に流す)

| 表 | 書く値 |
|---|---|
| `transcripts` | 文字起こしアプリからのときだけ。`body`・`dst`・`speaker`・`received_at` |
| `messages` | `seq`(サーバーの採番)・`dst`・`body`(指示コードならサーバーが作った文)・`kind`(`free` / `order`)・`icode`・`pos`・`source`(`web` / `transcript`)・`sent_at`。ここで `id` が決まる(= `mid`) |
| `message_targets` | 宛先の端末ごとに `message_id`・`device_id`・`via_at_send`(送った時の経路) |
| `transcripts.message_id` | 文字起こしアプリからのとき、決まった `messages.id` を書き戻す |

### 渡す

**端末へ**(`all` なら `reray/v1/down/all/text`、1台なら `reray/v1/down/dev-001/text`。QoS 1)

```json
{"v":1,"type":"text","src":"pc","dst":"all","seq":7,"mid":12,"ts":1791849600,"body":"北口に集合してください"}
```

### 流したあと

| 結果 | DB | 画面へ返すもの(HTTP の応答) |
|---|---|---|
| ブローカーが受け取った(PUBACK) | `messages.publish_state = sent`、`events`(`direction = down`、`result = sent`) | `{"id":12}`(文字起こしなら `{"id":12,"transcript_id":5}`) |
| 流せなかった | `messages.publish_state = failed`、`events`(`result = failed`) | 503 |

## 8. MQTT へのデータの渡し方(publish の決まり)

サーバー・端末・疑似端末ツールが MQTT に流すときの共通の決まり。

### 8.1 中身(ペイロード)の書き方

| 決まり | 内容 |
|---|---|
| 形式 | **JSON のオブジェクト1つ**を、文字コード UTF-8 で送る。1メッセージに複数件を詰めない |
| 余計なもの | 改行・空白は入れない(バイト数を減らす)。末尾に改行も付けない |
| 型 | 数値は数値のまま(`"seq":"42"` ではなく `"seq":42`)。真偽は `true` / `false` |
| 項目名 | `INTERFACES_2026-10-23.md` §2 のとおり(小文字・`_` 区切り) |
| 大きさ | 4 KB まで。超えたものは受け手が捨てる |
| 省く項目 | 値が無い項目は `null` にせず、**項目ごと省く**(例:電池が測れないときの `battery`) |
| バイナリ | 送らない(Base64 にもしない)。音声は【将来】の普段用だけ(`ARCHITECTURE_2026-10-23.md` §12) |

### 8.2 トピックごとの送り方

| トピック | 送る人 | QoS | retain | 受け取る人 |
|---|---|---|---|---|
| `reray/v1/up/{id}/signal` | 端末(LoRa のときは出口が代わりに) | 1 | しない | サーバー |
| `reray/v1/up/{id}/status` | 端末(遺言はブローカーが代わりに) | 0 | しない | サーバー |
| `reray/v1/up/{id}/ack` | 端末 | 1 | しない | サーバー |
| `reray/v1/down/{id}/text` | サーバー | 1 | しない | 端末 `{id}` |
| `reray/v1/down/all/text` | サーバー | 1 | しない | 全端末 |
| `reray/v1/down/{id}/ack` | サーバー【案】 | 1 | しない | 端末 `{id}` |

- **retain は使わない。** 後からつないだ端末に古い指示や古い状態が流れてしまうため。今の状態はサーバー(DB)が持つ。
- トピックの `{id}` と JSON の `src`(下りなら `dst`)は必ず同じにする。

### 8.3 接続のしかた

| 項目 | サーバー | 端末 | 疑似端末ツール |
|---|---|---|---|
| クライアントID | `reray-server`(固定) | 端末ID(`dev-001`) | 真似する端末ID |
| セッション | 持続する(`clean session = false`) | 持続する【修正案】 | 試す内容に合わせる |
| keepalive | 30秒【案】 | 30秒【案】 | 30秒 |
| 遺言 | 登録しない | `reray/v1/up/{id}/status` に `{"v":1,"type":"status","src":"{id}","online":false}`(QoS 1、retain しない) | 端末と同じ |
| 購読 | `reray/v1/up/#`(QoS 1) | `reray/v1/down/{id}/#` と `reray/v1/down/all/#`(QoS 1) | 試す内容に合わせる |
| 切れたとき | 自動でつなぎ直す | 自動でつなぎ直す | — |
| ユーザー名・パスワード | `.env` から読む | 端末に書き込む(git に入れない) | `.env` から読む |

- **MQTT のバージョンは 3.1.1 に合わせる。** 端末側でよく使うライブラリ(Arduino の PubSubClient)は 3.1.1 までしか対応していないため。ブローカーは 3.1.1 と v5 のどちらも受けられるので、v5 が必要になる普段用(【将来】)のアプリだけ v5 でつなげばよい。
- keepalive が 30秒だと、端末が黙って切れてから約45秒(30秒 × 1.5)でブローカーが遺言を流す。サーバー側の「90秒なにも届かなければ切れた」(`ARCHITECTURE_2026-10-23.md` §5)より先に気づける。

### 8.4 サーバーが流すときの順番

1. **先に DB に書く**(`messages`・`message_targets`。ここで `mid` が決まる)
2. `seq` を付ける(`pc` の連番。65535 の次は 0。再起動したら DB の最後の `messages.seq` の次から始める)
3. MQTT に流す(QoS 1)
4. **ブローカーの受け取り(PUBACK)を待ってから** `messages.publish_state = sent` にする。決まった時間内に返らなければ `failed`
5. `events` に `direction = down` で原本を残す

本部に届いた(`down/{id}/ack`)は、`messages` には書かず、`events` にだけ残す。`seq` は text と同じ `pc` の連番を使う。

### 8.5 例:サーバー(TypeScript + MQTT.js)

```ts
import mqtt from "mqtt";

// 接続。値は .env から読む(パスワードをコードに書かない)
const client = await mqtt.connectAsync(process.env.MQTT_URL!, {
  clientId: "reray-server",
  clean: false,          // 再起動中の QoS1 を取りこぼさない
  protocolVersion: 4,    // MQTT 3.1.1(端末に合わせる)
  keepalive: 30,
  reconnectPeriod: 1000, // 切れたら1秒後からつなぎ直す
  username: process.env.MQTT_USER,
  password: process.env.MQTT_PASS,
});

await client.subscribeAsync("reray/v1/up/#", { qos: 1 });

// 下りの text を流す(DB に保存して mid と seq を決めたあとで呼ぶ)
async function publishText(dst: string, mid: number, seq: number, body: string) {
  const topic = `reray/v1/down/${dst}/text`; // dst は端末ID か "all"
  const payload = JSON.stringify({
    v: 1, type: "text", src: "pc", dst, seq, mid,
    ts: Math.floor(Date.now() / 1000), // UNIX 秒
    body,
  });
  // QoS 1 なので、ブローカーの PUBACK が返ってから解決する
  await client.publishAsync(topic, payload, { qos: 1, retain: false });
}
```

### 8.6 例:手で流して試す(mosquitto_pub)

Git Bash などから(PowerShell は JSON の `"` の扱いが違うので、Git Bash を使う)。

```bash
# signal を1件流す(端末 dev-001 のふり)
mosquitto_pub -h localhost -q 1 -i dev-001 \
  -t 'reray/v1/up/dev-001/signal' \
  -m '{"v":1,"type":"signal","src":"dev-001","seq":42,"ts":1791849600,"code":2,"pos":3,"via":"wifi"}'

# 端末 dev-001 に届くものを見る
mosquitto_sub -h localhost -q 1 -v -t 'reray/v1/down/dev-001/#' -t 'reray/v1/down/all/#'
```

認証を付けたら `-u ユーザー名 -P パスワード` を足す(パスワードは履歴に残るので、検証用のものだけ使う)。
