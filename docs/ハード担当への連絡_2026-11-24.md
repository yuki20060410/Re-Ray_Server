## 3. 端末に守ってほしい決まり

### 3-1. 送り直しは `seq` も `ts` も最初の値のまま

「本部に届いた」が来ずに送り直すときは、**`seq` も `ts` も、最初に送った値を変えない**でください。時刻が分からなかったときは 0 のままです。

サーバーは「同じ端末・同じ `seq`・同じ `ts`」を 24 時間まで同じ信号とみなし、もう一度「本部に届いた」を返します。`ts` を送り直した時刻に変えると、10 分を過ぎた送り直しが**新しい信号として記録され、SOS が 2 件に見えます**。

- `ts` が 0 の端末は、10 分を過ぎたら中身(`code`・`pos`・`n`・`dir`)が同じときだけ同じ信号とみなします。
- 再起動で `seq` がたまたま前と同じになっても、`ts` が違えば別の信号として残ります。

### 3-2. 設定の `rev` は大きな数になる(32 ビットの符号なしで持つ)

`rev` は「変えた時刻(UNIX 秒)」と「前の版 + 1」の大きい方です(例 `1795498805`)。
サーバーや DB を作り直したときに、端末が覚えている前の版より小さくならないようにするためです(試験中に、ブローカーに残っていた版 4 より新しい設定が版 3 になり、無視されるのを見つけた)。
**端末は「前より大きいときだけ覚え直す」のままで大丈夫です。** 32 ビットの符号なし(2106 年まで)で持ってください。

```json
{"v":1,"type":"config","src":"pc","dst":"dev-001","seq":12,"ts":1795498805,"rev":1795498805,
 "channels":[{"ch":1,"kind":"direct","name":"本部"},{"ch":3,"kind":"group","name":"北班"}],
 "positions":[{"pos":1,"name":"本部テント"},{"pos":3,"name":"体育館前"}]}
```

- `channels`: 先頭が「本部」(1 対 1)。名前は 8 文字まで、1 台 8 個まで(お願いの上限のまま)。
- `positions`: 1,500 バイトに収まらないときは番号の大きい方を削り、`"positions_more": true` が付きます。一覧に無い番号は「ポジション 12」のように出してください。

### 3-3. つなぐ**前**に受信の処理を付けておく

`clean session = false` でつなぐと、切れている間に溜まっていた下り(text、本部に届いた)が**つないだ直後に**届きます。受信の処理を、つないだあとに付けると取りこぼします(サーバーの疑似端末で実際に取りこぼしました)。retain の `config` も、購読した直後に届きます。

### 3-4. モード

- 端末でモードを切り替えたら、**すぐ status を送って**ください(`"mode":"normal"` か `"emergency"`。ほかの値は捨てます)。
- 本部からの一斉切り替えは `reray/v1/down/all/mode` に届きます。切り替えて status で知らせてください。返事(ack)は要りません。

```json
{"v":1,"type":"mode","src":"pc","dst":"all","seq":9,"ts":1791849700,"mode":"emergency"}
```

### 3-5. チャンネルの文と指示

```json
{"v":1,"type":"text","src":"pc","dst":"dev-002","seq":4,"mid":1,"ts":1795498511,
 "ch":3,"from":"dev-001","from_name":"山田","body":"北口の点検が終わりました"}
{"v":1,"type":"text","src":"pc","dst":"dev-001","seq":8,"mid":13,"ts":1791849700,
 "icode":1,"pos":3,"requires_response":true,"ch":1,"from":"pc","from_name":"本部","body":"体育館前へ移動してください"}
```

- `ch` が無い文(一斉)は「全体」に入れてください。
- `requires_response` が `false` の指示には、了解・できない(ack_kind 4・5)を求めません。
- 返事(`ack_mid`)は今までどおり端末ごとです。

### 3-6. 音声

```
POST /api/voice
  Content-Type: audio/wav      (PCM 16 ビット。16kHz・モノラルを想定。8〜48kHz、ステレオも受け付ける)
  X-Device: dev-001            (登録した端末だけ)
  X-Channel: 3                 (その端末が入っているチャンネルだけ)
  X-Seq: 123                   (0〜65535)
  本体: WAV(16 秒・600KB まで)
→ 202 {"id": 45, "duplicate": false}
```

- 202 が来なければ、**同じ `X-Seq` で**送り直してください。10 分以内なら前の `id`(`duplicate: true`)が返り、二重には文字起こししません。
- 文字になった文は、§3-5 の形で**話した本人にも**届きます(`from` = 自分)。声が無かったときは何も届きません。
- 断るとき: 400(ヘッダの形)、413(大きすぎる)、415(Content-Type)、422(登録していない、チャンネルに入っていない、WAV でない・圧縮・16 ビットでない、16 秒を超える)。本文は `{"error":"コード","message":"理由"}`。
- 録音しながら書く WAV で、data の大きさを後から書き直せない(0 のまま)場合も受け付けます(残り全部を音として読む)。
- CPU だけの文字起こしなので、文字が届くまで数秒〜数十秒かかります。

### 3-7. 試すときの準備(管理画面)

1. **端末の登録**: 「端末の登録」で `dev-001` などを登録する。登録しないと、その端末あての文も、チャンネルも、音声も使えません(信号と状態は登録しなくても記録されます)。
2. **チャンネル**: 「チャンネル」でグループを作り、端末を入れる(音声はそのチャンネルの番号を `X-Channel` に)。
3. **捨てられたとき**: `GET /api/events?result=invalid&device=dev-001` で理由が分かります。
